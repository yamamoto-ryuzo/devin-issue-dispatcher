# 完了時スキル（done）

タスク完了前に、必ず以下の動作確認を実施してください。確認が取れないまま「完了」としないこと。

## 必須確認事項

1. **動作確認を行うこと**
   - 実装した変更が実際に動くことを、単なるコード記述の完了ではなく実行結果で示す
   - lint/型チェック/ビルドが通るだけでなく、機能として動作することを確認する
   - **スクリーンショットによる動作確認も行うこと**。画面・出力を視覚的に確認できる対象では、キャプチャを取得して見た目でも動作を確認し、証拠として保存する

2. **Playwright が利用可能なら Playwright で動作確認を行うこと**
   - UI/Web 系の変更は、ブラウザを実際に起動して該当画面・操作を確認する
   - 画面が表示される・ボタンが動く・データが正しく描画されることを目視レベルで確認する
   - 確認時の画面キャプチャを保存し、完了報告・クローズ時コメントの証拠として使えるようにする

3. **他のアプリとの連携がある場合は、必ず連携確認を行うこと**
   - API・ファイル・プロトコル等で他アプリと連携する変更は、連携先が実際に受け取れるかを確認する
   - 片側だけの実装完了で終えない

4. **QGIS などのアプリ連携がある場合は、当該アプリを実際に立ち上げて連携操作を確認すること**
   - QGIS/QField 等との連携は、アプリを起動して実際のデータ受け渡し・表示を確認する
   - 「起動できるはず」ではなく、実際に立ち上げて動いたことを証拠にする
   - スクリーンショット取得機能（例: QGIS 側の screenshot プリミティブ）がある対象はそれを使い、画面状態を保存する

5. **DOCS を整理すること**
   - 変更に伴い README/CHANGELOG/docs/ の更新が必要な箇所を同時に直し、実装とドキュメントの乖離を残さない
   - リポジトリの規約がある場合はそれに従う（例: QGIS プラグインの変更はそのプラグインの CHANGELOG.md に記録）
   - 必要に応じて、完了した機能のスクリーンショットをドキュメントに掲載する（動作確認で取得したキャプチャを利用してよい）
   - 課題と無関係なドキュメントの大掛かりな整理・改訂は行わない（最小差分の範囲に留める）

6. **AI との連携を確認すること**
   - AI 制御経路（bridge / pluginInfo / describe_plugins / MCP / pyeval 等）を持つ対象では、実装した機能が AI 経路から発見・実行できることを確認する
   - bridge や pluginInfo() 等の既存インターフェースの形式を壊していないかも合わせて確認する

## 確認が取れない場合

- 環境制約で動作確認ができない場合は、**何を確認できなかったかを明記**して `needs-review` 相当として扱う
- 未確認のまま「完了」を装わない

## 課題（issue）をクローズする場合

- クローズする前に、**対応結果を issue コメントとして残す**（何を・どう変更したか、動作確認の結果・証拠）
- **極力スクリーンショットを添付する**。UI/画面・表示系の変更では、動作確認で取得した画面キャプチャをコメントに添えてからクローズする
- コメントの投稿を確認してから `gh issue close` でクローズする（サイレントクローズしない）
