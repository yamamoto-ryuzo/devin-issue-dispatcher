# 切り分けスキル（split）

このセッションでは課題の実装状況を切り分けます。**コード変更は行わない**（確認・検証は行う）。

## やること

1. **実装状況を調査** — `git log`、コードの現状、関連 PR の履歴から、issue で要求されている部分がどこまで実装済みかを確認する
2. **実装済み部分を「完了時スキル」に従って検証する**
   - 動作確認（変更が実際に動くか）
   - Playwright が使えるなら UI を実起動して目視確認
   - 他アプリ連携があれば必ず連携確認（QGIS 等は実際に起動）
3. **検証結果で分岐**

   **✅ OK の場合（実装済み部分が動作する）**
   - 元 issue に `devin:done` ラベル＋「実装済み部分を完了として切り分け。残りは新規 issue #M に移行」コメント
   - **元 issue を `gh issue close` でクローズ**
   - 残作業を `[残課題]` タイトルの新規 issue として `gh issue create`
   - 新 issue がさらに実装済み/未実装に分かれる場合は、この切り分けを再帰的に実施する

   **❌ NG の場合（実装済みと見えたが動かない）**
   - 完了扱いにしない — `devin:done` ラベルがあれば除去（`gh issue edit --remove-label devin:done`）
   - 「実装済みと見えたが検証 NG」理由をコメントして課題に戻す（issue は open のまま）
   - そのまま実装タスクとして扱うため `devin` ラベルを付けるか、再度評価対象に戻す

4. **最後に出力ブロック**（新 issue を作った場合のみ newKey を入れる）

```
<!--split
{"newKey":"<owner/repo> issue#<新issue番号>","verified":"ok|ng"}
split-->
```

## 注意

- 「実装済みっぽい」ではなく、動作確認で証明できた部分のみ完了扱いにする
- 切り分け先でも同じループを回し、実装が混在したままの課題を残さない
- 新 issue が作れなかった場合は `newKey` を `null` にし理由を説明する
