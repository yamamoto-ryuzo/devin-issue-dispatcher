# 課題整理スキル（survey）

このセッションは【課題の整理・提案のみ】を行います。コード変更・コミット・Issue起票は禁止です。

## 目的

ユーザーが入力した「やりたいこと・目的」を起点に、後述の抽出レベルの範囲で
目的達成に必要な作業を検討し、起票すべき Issue の候補（タイトル案・本文案）を整理する。
目的が指定されない場合は、リポジトリの現状から改善・修正候補を抽出する。

## 抽出レベル

プロンプトに【抽出レベルN】の指定がある場合、その粒度に従う:

- **レベル1（文言の整理のみ）**: 入力文言をそのまま整理・構造化して Issue 候補化する。
  文言に含まれない作業・改善・関連機能は追加しない。リポジトリの確認は重複確認と文脈把握のみ
- **レベル2（忠実に抽出）**: 入力文言を拡大解釈せず忠実に、目的達成に直接必要な作業のみを候補化する。
  推測による関連機能・改善の追加提案はしない
- **レベル3（関連機能も含む）**: 入力文言を起点に、目的達成に有効な関連機能・周辺の改善も
  含めて積極的に候補化する

指定がない場合はレベル2相当として扱う。

## やること

1. 入力された目的・要望（および添付画像があればその内容）を把握する
2. `gh issue list` / `gh pr list` で既存の課題を確認し、必要に応じてコードを読む（読み取りのみ）
3. 目的達成に必要な機能追加・エラー修正・改善を洗い出す
4. 各候補に対して以下を整理する:
   - **タイトル案**: 簡潔で内容が分かる日本語（必要に応じて `[機能追加]`/`[不具合]`/`[改善]` 等の接頭辞）
   - **本文案**: 目的・背景 / やること（受け入れ条件）/ 補足（参考ファイル・既存実装との関係）
5. 既存 Issue・PR と重複するものは提案しない

## 出力形式

提案一覧の後、**最後に必ず**以下のブロックを出力する:

```
<!--issues
[{"title":"タイトル案","body":"本文案（Markdown）"}, ...]
issues-->
```

このブロックが検出されるとパネル側に Issue 候補として一覧表示され、
ユーザーが個別に起票する。出力が長くなる場合はブロックを複数回に分けてよい
（パネル側で全ブロックを重複排除しつつマージする）。省略・変形はしない。
**配列は必ず `]` で閉じて終わること**（閉じ忘れるとパース失敗になり候補が反映されない）。
