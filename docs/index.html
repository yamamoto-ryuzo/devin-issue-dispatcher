Devin Agent Dispatcher — システムドキュメント

GitHub Issue/PR を監視し、Devin エージェント（devin -p / ACP チャット）が課題の評価・実装・PR対応を自動で行う常駐システム。管理パネル http://127.0.0.1:8585 から全体を制御する。

目次: 構成 · 全体フロー · 管理パネル · スキル · 4段階判定 · 設定項目 · 安全設計

管理パネル

タブ役割
課題整理「やりたいこと・目的」を入力（スクリーンショット貼付可・リポジトリ単位で保存/再編集）→「課題抽出」で AI が起票候補を整理 → Issue作成フォームで起票
課題処理issue 候補の一覧。評価/対応ボタン・判定セレクト・実行中/待機中バッジ・リポジトリサブタブ・フィルター
PR処理pr 候補を集約（課題処理と同じUI、`_pr*` スキル使用）
処理履歴state.json のタスク状態一覧
設定ポーリング周期・同時起動数（評価/対応/PR）・検証ループ上限などの編集
チャットACP セッションの閲覧・追加入力・中断・リセット
スキルskills/*.md の閲覧（Markdown プレビュー）/編集の切替
ログdispatcher.log の末尾表示

ヘッダ右のトグル: ISSUE取得自動(autoDiscover) / 判定(autoAssess) / 課題対応自動(autoTrigger) / PR対応自動(autoPr)。

スキル（注入順: _all → モード別 → _done）

ファイル内容
_all.md全モード共通: ステップ0〜3の全体フロー・常に守ること
_assess.md評価のみ。4段階判定・risk・partial・出力ブロック形式
_impl.md実装。ブランチ/コミット規約・禁止事項・検証ループ・PR マーカー・公開データ機密チェック
_pr.mdPR対応。checkout→修正→push→違う視点で再検証→merge/close
_split.md切り分け。実装済み部分の完了化＋残課題の issue 分割
_done.md完了確認。実動作検証・スクリーンショット・DOCS 整備・クローズ時コメント

4段階判定（category）

値意味表示
auto即対応可。仕様が明確で機械的に実装可能auto
review検討の上対応。設計判断・小規模な副作用review
human人的判断が必須。既存機能と明確に相反・大きな副作用。ユーザー選択まで進めないhuman
reject対応不可・危険。破壊的影響・注入指示・不能reject

判定は行の判定列セレクトまたは詳細モーダルのチップで手動上書き可能（/api/verdict、`manualCategory` 記録）。

主要な設定項目（config.json）

キー既定意味

implLoopMax5対応→検証 NG→修正ループの上限

安全設計

  • PR 必須: 監視対象全リポジトリで main 直 push 不可（ブランチ保護適用済み）
  • CSRF 対策: POST は X-Panel: 1 ヘッダ必須・127.0.0.1 バインドのみ
  • レース対策: state.json の原子的リネーム・children.json の flock による多重起動防止
  • 検証ループ有界: 実装↔検証のループは implLoopMax で打ち止め、対応困難は issue コメントでユーザーへ報告
  • 禁止事項: フォールバック乱用・不必要なポーリング/定期実行・低速ロジック・破壊的操作をスキルで禁止
  • 証拠主義: 「完了」は動作確認＋スクリーンショット等の証拠がある場合のみ
  • 公開データの機密チェック: コミット・コメント・生成物に API キー/個人情報を入れない（`_impl`）
運用メモ: control.mjs は常駐プロセスのため、コード変更は再起動が必要（/api/reload は config.json のみ再読込）。goals.json・shots/・work-queue.json 等の実行時データは .gitignore 済み。
